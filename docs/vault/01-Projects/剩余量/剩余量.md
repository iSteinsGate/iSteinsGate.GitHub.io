
```anyblock
[list2node]
- 剩余量
	- 必要条件
		- 长期
		- 不拆零
		- 自动计算剩余量
		- 单次取整/总量取整
	- 核心
		- 剩余量=`申领数量*基本剂量-执行卡数量*单个执行卡用量`
	- 申领
		- 组合情况
			- 单个
				- 剩余量足够的，但未申领的执行卡，不需要申领
				- 剩余量不够，需要带上剩余量重新计算申领数量
			- 合组（剩余量药品+普通药品；剩余量药品 +普通药品+剩余量药品+自备药）
				- 剩余量都足够,不需要申领
				- 剩余量只够任一，需要申领
				- 剩余量都不够，带上剩余量重新计算申领数量
		- 申领
			- 计算剩余量=申领数量*基本剂量+上次剩余量-本次执行卡总剂量
			- 本次剩余量分摊到未申领的执行卡
			- 剩余量满足的执行卡，标记不需要申领
			- 生成剩余量记录
			- 库存不足继续申请的剩余量处理流程
		- 发药
			- 剩余量足够的需要标记执行卡完成,并处理带出的耗材和处置等
		- 撤销申领
			- 完全撤销，需要根据撤销的发药重新计算剩余量，已分摊完成的执行卡需要恢复到可申领状态
			- 撤销部分，需要重新计算剩余量`合组的任一剩余量不够`需要恢复成可申领
	- 申退 `暂不考虑`
		- 申退，根据申退的数量重新计算剩余量，并处理已分摊未申领的执行(`由剩余量分摊的`)  
		- ❓如果申领了多次，第二申领使用了第一次申领的剩余量，此时申退第一次，会出现剩余量无法计算的情况
		- > [!faq] 100ml/瓶，单次50ml.一天三次；第一天申领5瓶剩余量50ml, 第二天申领1瓶，剩余量0，此时申退第一天的2瓶，
		- > [!faq] 即会把第一天50ml剩余量撤销，但是由于第二天该剩余量已经用了，如果撤销，会导致第二天药不够量
		- 撤销申退
			- 重新计算剩余量
	- 滚执行卡
		- 生成执行卡根据剩余量分摊执行卡，并重新计算剩余量
		- 剩余量足够的执行卡标记已完成，并处理带出医嘱，耗材费用
		- 剩余量部分足够不处理
```
