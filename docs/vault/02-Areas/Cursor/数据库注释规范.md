

## 表定义
使用标准的SQL DDL 语句

表注释标准格式
```sql
COMMENT ON TABLE table_name IS '【实体类型标签】业务描述 - 详细说明。[元数据] 业务重要性:X ;
```
示例
```sql
COMMENT ON TABLE patients IS '【核心实体】患者档案表 - 存储患者身份信息和档案状态。业务重要性:最高 | 数据敏感度:高 ;
```
## 表关系定义
1. **物理外键约束** (FOREIGN KEY语法) - 准确率99%+
2. **明确注释+标准命名** - 准确率85-90%
3. **仅标准命名** - 准确率70-80%
4. **模糊注释** - 准确率50-60%
5. **无任何标识** - 准确率<30%

### 关于逻辑外键定义
a) 一致的命名约定

```sql
CREATE TABLE orders (  
    id INT PRIMARY KEY,  
    user_id INT COMMENT '关联到users表的id', -- 通过命名和注释  
    product_id INT -- 根据命名模式推断关联products表  
);
```
b)详细的列注释
```sql
CREATE TABLE order_items  
(  
    order_id   INT COMMENT '外键，逻辑关联到orders表的id字段，无物理约束',  
    product_id INT COMMENT '外键，指向products主表，应用层维护一致性'  
);
```

### 使用标准化注释模板（增强）

在注释中使用一致的格式，例如：
```text
[关系类型] 关联表:字段 (维护方式)
```
例如：
```text
[1:N逻辑外键] 关联到:orders:id (应用层维护)
```
示例
```sql
-- PostgreSQL
COMMENT ON COLUMN order_items.product_id IS '外键关系：products.id (逻辑关系，无物理约束)';
```

## 元数据标签定义

实体类型标签：`【核心实体】`、`【扩展实体】`、`【明细实体】`、`【字典表】`
关系类型标签：`[逻辑外键]`
字段类型标签：`[状态码]`、`[字典值]`
## 枚举定义 

注释中使用标准模板
```text
[状态码]状态含义：状态值枚举
```
例如：
```sql
COMMENT ON COLUMN user.status IS 【状态码】用户账户状态: 1=激活, 2=禁用, 3=待验证, 4=已删除(软删除)
```

## 字典定义
注释中使用标准模板
```text
[字典代码] 字典值含义：字典代码

```
例如：
```sql
COMMENT ON COLUMN patient.relation IS 【字典代码】患者关系: HZGX
```

## 总结
### 1. 表注释标准格式

```sql
COMMENT ON TABLE table_name IS '【实体类型标签】业务描述 - 详细说明。[元数据] 业务重要性:X | 其他属性';
```

**示例**：

```sql
COMMENT ON TABLE patients IS '【核心实体】患者档案表 - 存储患者身份信息和档案状态。业务重要性:最高 | 数据敏感度:高 | 合规要求:HIPAA';
```

### 2. 逻辑外键注释标准格式

```sql
COMMENT ON COLUMN table_name.column_name IS '[关系类型] 关联到:target_table:target_field (维护方式)';
```

**示例**：


```sql
COMMENT ON COLUMN visits.patient_id IS '[1:N逻辑外键] 关联到:patients:id (应用层维护，无物理约束)';
```

### 3. 字典代码注释标准格式

```sql
COMMENT ON COLUMN table_name.column_name IS '[字典代码] 业务含义: 字典编码 (字典表说明)';
```

**示例**：

```sql
COMMENT ON COLUMN patients.relation IS '[字典代码] 患者关系: HZGX (基础字典表，key_code存储值)';
```

### 4. 状态码注释标准格式

```sql
COMMENT ON COLUMN table_name.column_name IS '【状态码】状态含义: 值1=描述1, 值2=描述2, ...';
```

**示例**：

```sql
COMMENT ON COLUMN patients.status IS '【状态码】患者档案状态: 1=正常, 2=归档, 3=注销, 4=黑名单, 9=待审核';
```

### 5示例
```sql
-- =============================================
-- 创建就诊记录表 (明细业务实体)
-- =============================================
CREATE TABLE visits (
    id BIGSERIAL PRIMARY KEY,
    visit_number VARCHAR(30) NOT NULL UNIQUE,
    patient_id INT NOT NULL,
    doctor_id INT NOT NULL,
    department_id INT NOT NULL,
    visit_type VARCHAR(10) NOT NULL,
    visit_date DATE NOT NULL,
    status SMALLINT NOT NULL DEFAULT 1,
    diagnosis TEXT,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE visits IS '【明细实体】就诊记录表 - 存储患者每次就诊的详细信息。业务重要性:高 | 数据量:大 | 分区策略:按visit_date范围分区';

COMMENT ON COLUMN visits.id IS '【主键】就诊记录唯一标识符';
COMMENT ON COLUMN visits.visit_number IS '【业务键】就诊号，格式:V-YYYYMMDD-NNNNN';
COMMENT ON COLUMN visits.patient_id IS '[1:N逻辑外键] 关联到:patients:id (应用层维护，无物理约束)';
COMMENT ON COLUMN visits.doctor_id IS '[N:1逻辑外键] 关联到:doctors:id (应用层维护，无物理约束)';
COMMENT ON COLUMN visits.department_id IS '[逻辑外键] 关联到:departments:id (应用层维护)';
COMMENT ON COLUMN visits.visit_type IS '[字典代码] 就诊类型: JZLX (门诊/急诊/住院等字典值)';
COMMENT ON COLUMN visits.visit_date IS '【业务日期】就诊发生日期，非系统录入时间';
COMMENT ON COLUMN visits.status IS '【状态码】就诊记录状态: 1=已挂号, 2=已就诊, 3=已取消, 4=已退号, 5=已完成';
COMMENT ON COLUMN visits.diagnosis IS '【医疗信息】初步诊断结果，医生填写，敏感医疗数据';
```
