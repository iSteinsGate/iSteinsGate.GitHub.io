## rules
完成本次修改后，提炼出 cursor rules 补充到 rules 文件中

1. 借助 MCP ，让 AI 直接读取需求文档、设计稿、接口文档等等
2. 复杂的任务不要直接让 AI 动手写，这样容易返工。可以增加如下的规则，确认 AI 理解对了再动手：

```html
当你需要完成一个任务时，请遵循以下步骤：

1. 先别动手改代码
2. 输出你对本次任务的理解
3. 输出你的计划和实现方案
4. 等待我的审核，如果我提出修改意见，请根据我的意见修改计划和实现方案
5. 在我确认没问题之后，再动手改代码

```
注意：
1. 对于冗长的任务，可以将其计划存入一个文件，以便在不同实例中应用相同的方向。文件存放位置遵循就近原则


## 正确使用的 12 条准则：  
  
1. 预先定好 5-10 条明确的项目规范，让 Cursor 知道你的项目结构和约束。对于老代码库，可以试试 /generate rules。  
  
2. 提示词要具体。限定范围，像写一份简要的技术说明那样，把技术栈、功能要求和约束都讲清楚。
  
3. 建议模块化开发，逐个文件来做；每次处理一小部分，集中精力生成、测试和检查。  
  
4. 先写测试，确定测试用例，然后让 AI 生成代码，直到所有测试都通过。（PS：参考TDD模式）  
  
5. 务必检查 AI 的输出，先不着急Apply。发现问题要彻底改对，然后告诉 Cursor 这些改动，让它学习。  
  
6. 用 @ file, @ folders, @ git 把 Cursor 的注意力范围限定在你关心的代码部分。  
  
7. 把设计文档和任务清单放在 .cursor/ 目录里，这样 Cursor 就能充分了解接下来该做什么。这里推荐搜一下“AI花生”的插件。  
  
8. 如果 AI 生成的代码不对，别光解释了，先放弃吧。直接自己改，Cursor 从你的修改中学得比解释快。  
  
9. 利用聊天历史，可以在旧提示词基础上迭代优化，不用每次都从头开始。  
  
10. 有目的地选择不同的模型，各有所长。Gemini 适合需要精确的场景，Claude 适合需要广泛理解的场景。  
  
11. 遇到新的或不熟悉的技术栈，把文档链接粘贴进去。让 Cursor 逐行解释遇到的错误以及如何修复。  
  
12. 大项目让它先花时间索引，可以放在晚上进行；同时限制上下文范围，保持操作流畅。

## **Cursor交互技巧**：

1. 先让Cursor阅读`schema_digest.md`
2. 再提供具体业务需求
3. 使用"Edit"功能逐步优化生成的SQL

大型文件处理技巧
1. **右键选择"On File"** 而非"On Selection"处理整个文件
2. **使用符号折叠**：在SQL文件中使用`-- region`和`-- endregion`标记折叠区块





### 使用 @Docs：获取官方权威信息

`@Docs` 就像是你的专属技术顾问，它直接连接到各大框架和工具的官方文档。

**最适合这些场景：**

- **查 API 用法**：想知道某个函数的具体参数和返回值
- **学习新功能**：框架升级后的新特性介绍
- **了解最佳实践**：官方推荐的代码写法
- **解决配置问题**：正确的安装和配置步骤

**实际使用示例：**

```text
@Docs Next.js
我想实现动态路由，支持多层级的路径参数，应该怎么配置？
```

这样提问，AI 就会基于 Next.js 的官方文档给出最准确、最新的解答。
### 使用 @Web：借鉴社区智慧

`@Web` 则像是一个经验丰富的同事，它会搜索网络上的技术博客、GitHub 讨论、Stack Overflow 问答等。

**最适合这些场景：**

- **寻找教程**：有没有人写过类似功能的实现教程
- **对比方案**：A 方案和 B 方案哪个更好
- **解决报错**：这个错误信息别人是怎么解决的
- **了解趋势**：最新的技术趋势和社区讨论

**实际使用示例：**

```text
@Web
React 19 有哪些性能优化的新特性？社区的评价如何？
```

## 高级应用：连接内部文档系统

如果说前面两个工具解决的是"通用问题"，那么 MCP（模型上下文协议）解决的就是"个性化问题"。

### 为什么需要内部文档？

每个公司、每个项目都有自己的"个性"：

- **内部 API**：公司自研的服务接口
- **编码规范**：团队约定的代码风格
- **业务逻辑**：这个系统要解决什么具体问题
- **历史决策**：为什么当初选择了这个技术方案

这些信息在互联网上是找不到的，只存在于你们的内部文档中。

### MCP：让 AI 读懂你的内部资料

MCP 就像是在 Cursor 和你的内部系统之间搭建了一座桥梁。通过这座桥，AI 可以：

- 读取你们的 Confluence 文档
- 访问 Google Drive 中的技术规范
